## Crowd Voting Storage

If voting is enabled in the builder, visitors can submit one coverage assessment plus zero or more
shade-source checkboxes per pseudonymous visitor and stop. The app keeps the community result separate
from the admin-reviewed stop dataset, and the configured threshold controls when a unique leading
coverage status is reported.

Repeated-voting protections are enabled by default. Anonymous voting uses separate server-keyed HMAC
pseudonyms for the visitor and network, never stores raw IP addresses or browser headers, limits one
vote per network and stop, applies visitor/network/stop velocity limits, and serializes each database
check with its write. IPv6 privacy addresses within the same /64 are treated as one network. Interim
counts are hidden by default, and a result must meet the configured vote threshold, winning share, and
margin before it is called consensus.

For materially stronger integrity, enable **Require account sign-in** in the builder and configure
Streamlit OIDC. Authenticated votes are keyed to the provider subject instead of network metadata:

```toml
[auth]
redirect_uri = "https://YOUR_APP_HOST/oauth2callback"
cookie_secret = "GENERATE_A_DIFFERENT_LONG_RANDOM_SECRET"
client_id = "YOUR_OIDC_CLIENT_ID"
client_secret = "YOUR_OIDC_CLIENT_SECRET"
server_metadata_url = "https://YOUR_PROVIDER/.well-known/openid-configuration"
```

Authentication configuration is provider- and host-specific. Never commit these values. Anonymous
controls still cannot stop a determined attacker who rotates networks, and client IP metadata is not a
cryptographic identity. High-stakes binding polls should require authentication and additionally use
an edge CAPTCHA/WAF, eligibility controls, and external abuse monitoring.

The app works locally with `.shade_gis_votes.sqlite3`. Durable hosted voting should use PostgreSQL
14+ in the researcher's own provider account. Stop-GIS does not host, own, or centrally retain that
database or its credentials. Configure both values directly in the host's server-side secret manager:

```toml
STOP_GIS_VOTE_DATABASE_URL = "postgresql://RUNTIME_USER:PASSWORD@HOST:5432/DATABASE?sslmode=require"
STOP_GIS_VOTE_FINGERPRINT_SECRET = "YOUR_BROWSER_GENERATED_SECRET"
```

PostgreSQL schema changes never run from normal app requests. Follow `DEPLOYMENT.md`: migrate once
with an owner role, grant a separate least-privilege runtime role, verify CRUD access, and then deploy
the runtime URL. The app uses bounded connection pooling and query timeouts. A configured PostgreSQL
failure is reported and never silently falls back to SQLite. Keep the fingerprint secret stable;
rotating it changes pseudonymous identities. Local SQLite remains suitable only for local evaluation.

## Publish To GitHub

Create a new GitHub repository named `@@REPOSITORY_NAME@@` and push these files:

```powershell
./deploy_to_github.ps1 -Mode create -RepositoryName "@@REPOSITORY_NAME@@" -Branch "main" -CommitMessage @@COMMIT_MESSAGE_LITERAL@@ -Visibility private
```

Or publish into a pre-existing private repository:

```powershell
./deploy_to_github.ps1 -Mode existing -RepositoryName "@@REPOSITORY_NAME@@" -Branch "main" -CommitMessage @@COMMIT_MESSAGE_LITERAL@@
```

The script requires Git and the GitHub CLI (`gh`) with an authenticated account.
For existing private repositories, the authenticated account must already have access to the target repository.
If Windows blocks the downloaded script, run `Unblock-File .\deploy_to_github.ps1` once and retry.
Before committing, the script prints `git status`, `git diff --stat`, and a staged diff summary, then asks you to type `PUBLISH`. Add `-Yes` only when you intentionally want non-interactive publishing.

## What The Publish Script Does

For a new repository, the helper initializes Git in the extracted bundle, stages only generated app files, commits those files, creates the GitHub repository, and pushes the branch. Public repository creation is blocked unless you explicitly add `-AllowPublicTarget`.

For an existing private repository, the helper verifies repository visibility when it can, clones the target repository into a temporary `_shade_gis_publish_*` folder under PowerShell's temp path, checks out the requested branch, copies generated app/runtime files into `preview_app/`, commits any changes, pushes back to GitHub, and cleans up the temporary folder. A legacy generated public app already hosted from root `app.py` is upgraded in place so its active Streamlit entrypoint cannot remain stale; a Stop-GIS builder root entrypoint is explicitly protected. Other protected files such as `.git/`, `.github/`, `.streamlit/`, `README.md`, `LICENSE`, `.env*`, and `secrets.toml` are not copied in existing-repository mode.
